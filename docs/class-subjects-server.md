# Class subjects: server contracts

Report cards remain class-staff-wide ON and OFF, including teachers assigned no subjects, by the owner's review-5 decision (2026-10-08).

ON saved-work authorization remains the single ID predicate in `SubjectFence::allowsWork`; general lesson plans retain shared access. ON linked saved work displays the subject's current name everywhere, including hidden subjects; unlinked work displays its saved text. Renaming does not write saved text. OFF displays the original text. An ON edit that omits `subject` preserves its snapshot and link, including an unchanged-ID-only edit. Explicitly making a named/linked plan general requires access to the original work and an unrestricted assignment; the model enforces both. Clients can request that choice with `subject: null, class_subject_id: null`. A date-only edit selects the existing general plan, or the sole permitted named plan when no general plan exists; several permitted named plans require an explicit choice (409). An empty day may still create a general plan. An unchanged subject ID can reference existing hidden work without making a new picker choice. Other lesson-plan prose retains the whole-object replacement contract. ID-only choices resolve the subject snapshot and key before create/update/by-day collision checks, so they behave like ID-plus-name choices. ON summaries group linked work by class_subject_id with current subject-name headings; NULL links retain saved-key grouping. Each ON by_subject row adds subject_identity, a JSON-encoded ['id', ID] or ['text', saved key] tuple used as the teacher, office and family rendering key; equal display names cannot merge their rendered rows. OFF summaries have no added key. Individual rows, details, save responses, family marks and exports also display current linked names. OFF request semantics remain origin/main's.

The tool middleware reads the assignment for its check, then the tool controller writes without re-reading subject permission. A write authorized immediately before revocation may complete. This is the existing legacy property; tool writes do not acquire the school mutex. Later requests see the new restriction.

ON curriculum resolves guide links per class. No class means the union of links from permitted subjects in led classes. All subjects in one class means only that class's links, also for a class-scoped request. OFF requests without a class retain the original whole-school guide. Teacher subject-list responses omit office guide/tool metadata.

ClassSubjectHttpRequest owns organisation-keyed capability decisions and complete organisation rows already loaded by main for exactly one HTTP kernel invocation; its finally block clears them, including on exceptions. Console, queue and scheduled contexts never store a memo. OFF rules, helpers, serializers and model saves share the HTTP decision, with at most one primary-key organisation SELECT when main has not already loaded it. ON model writers still recheck current capability under their existing school/current-row locks; outside HTTP, writers read fresh.

## Activation and reactivation

Use `php artisan class-subjects:initialize --masjid=ID --dry-run` to preview, and `--enable` to activate. Dry run is ordinary autocommit SELECTs: no transaction, locking read or write. MySQL's normal metadata locks on SELECTs are not eliminated; these are not school row locks that block ordinary FK-backed writes. A preview can observe concurrent changes between statements. Activation recomputes the same report under its school mutex. LOSS lines apply only to translated rows whose access changes in this run. Pacing losses require a guide for the class's current grades (or its seed grades when empty) that the legacy assignment could access; unchanged rows produce no losses. Combined-name NOTEs and order warnings are retained. Preview reads grouped work counts once per table per school, deduplicates loss lines before allocation and streams one class report at a time. Equal school-list positions produce an entry-order warning; ties break by id.

A staff row translates only if both `class_subjects_mapped_at` and `class_subject_ids_edited_at` are NULL and a prior deliberate disable has not recorded its ID in the activation marker's `untranslated_staff_ids`. The former records activation translation; the latter records an explicit ON office ID choice, including newly created ON assignments. Thus fresh OFF-created rows without either fact translate on activation; previously translated/office-chosen rows never translate again. Their IDs, activation audit snapshot and timestamps survive reactivation. The edit-marker reactivation blocker was removed. NULL remains stored as NULL and prints `all subjects`. Late OFF inserts without either authority fact fail closed while ON until an explicit office choice. An already-ON initializer rerun reports no subject access for these rows and does not translate them. Disable records those staff row IDs in activation history, so subsequent enable keeps them fail closed without inventing a translation or office-choice timestamp. This does not prevent newly created OFF rows from translating. An explicit office choice repairs a retained row and persists normally through subsequent disable/enable.

Only guide columns absent from the applicable school subject list can be skipped during seeding. Columns split on `&`, whole-word `and`, `/` or `,` are skipped when all parts match the class's existing/planned subjects by SubjectKey and the fixed aliases (ELA/English Language Arts and Arabic/Arabic Language). Explicit school-list subjects are always seeded. Setup reports the combined column and applicable grades. Office creation remains explicit and allowed; saved guide content is not altered. The same seeding function serves setup, ON lifecycle and add-for-current-grades.

## Deliberate disable

Generic capability toggles cannot switch this feature OFF after activation. Use `php artisan class-subjects:disable --masjid=ID --dry-run`. The real command takes the school mutex, builds/rechecks the report and locks current staff rows, then updates legacy subjects and flips OFF in one transaction. Blockers prevent all writes. Subjects, links, IDs and their authority facts remain stored.

Disable reads effective authority through SubjectFence::assignedIdsForRow, the same function as the ON fence. A row with neither provenance timestamp is reported as `untranslated, legacy value kept`, needs no acceptance, and receives no staff-row write: its raw legacy value (including SQL NULL, [], and original JSON formatting) is left exactly as stored.

Disable restores an unedited translated staff row's exact recorded legacy value. Activation copies the stored legacy JSON directly (SQL NULL is recorded as JSON null); missing SQL NULL provenance is distinct from recorded legacy NULL. `class_subjects_mapped_at` identifies translated rows and `class_subject_ids_edited_at` identifies office changes, including ON-created rows. An explicit unchanged office choice does not mark a translated row edited. Previously translated rows lacking provenance fail closed for a restricted disable choice.

Edited or ON-created rows with NULL IDs become legacy NULL without acceptance. Restricted edited/created rows (including empty, malformed or foreign IDs) are INEXPRESSIBLE and require the staff row ID in `--accept-unrestricted=ROW_ID,ROW_ID`, becoming legacy NULL when accepted. Missing, foreign-school, unnecessary and malformed acceptances are refused. No grant-equivalence guess is used. Dry runs write no legacy value or other data, and a blocker prevents every write. IDs and provenance survive disable and re-enable unchanged.

Hidden OFF-to-OFF capability no-ops write neither an override nor a ledger row. An activated school's own class-subject history is visible ON or OFF through main's unchanged latest-25 query. Other capability ledger policies remain intact.

## Office teacher editor and names (2026-10-08)

When `masjid.capabilities.class_subjects` is true, the office teacher editor sends only `class_subject_ids` (never `class_subjects`). Each newly selected class needs an explicit NULL (All subjects), [] (No subjects), or its chosen IDs. A removed class leaves `class_ids` and the ID map; unchanged classes stay selected but are omitted from the map so the server preserves their limits. Existing hidden choices remain available as `<name> (hidden)`; newly assigned classes offer only visible subjects, in class order. The editor reads the existing office `GET /api/admin/masjids/{masjid_id}/groups/{group_id}/subjects` on tick/expand, caching one catalog per class for the modal's life. Opening a many-class edit does not fetch catalogs. Late detail replies cannot replace a later ON modal.

ON-only display additions:
- Teachers index and invite/update replies: each `classes[]` adds `class_subject_names`, NULL for all, [] for none, otherwise ordered `{id, name, position, hidden_at}` descriptors alongside the existing `class_subject_ids`.
- Office groups index: each `teachers[]` adds the same `class_subject_names`; group detail now adds `teachers[]` with id, name, legacy subjects (retained compatibility field), IDs and name descriptors. These names disclose only this school's class subjects, including hidden choices.
- The `class_staff` CSV adds a final `Subjects` column when ON, with All subjects / No subjects / ordered names and `(hidden)`. The ON writer batches users and catalogs per 500-row chunk. A missing/foreign named ID yields Subjects unavailable, never All subjects. The legacy OFF writer and columns remain unchanged; its pre-existing populated-export failure from a missing `GroupStaff::user` relationship is outside this brief and remains present.
- `POST .../subjects/add-for-current-grades` adds `meta.subjects_added` (the actual insert count from the transaction). Zero shows `This class already has the subjects for its current grades.`; a positive count shows `Subjects for current grades added.`. A later catalog-reload failure retains the resolved sentence and the server's failure words.
- ON assignment membership and missing-explicit-choice refusals now use validation keys `class_subject_ids.<class_id>` with unchanged sentences. Wildcard item errors already include that class ID. The editor places every message under that class; unkeyed map refusals appear under selected classes, and other form errors use the existing banner/fields.

OFF teacher payloads, the legacy three-subject editor, groups responses and requests remain pinned by the unchanged protected suites plus a new complete response fixture in `ClassSubjectsTeacherEditorTest`. The Grades shrink/wrap styles are applied only with the ON prop. Setup's already-ON rerun already excluded unchanged rows' losses; the new Artisan regression verifies a summary with 0 subjects, 0 mappings and 0 losses, without changing the initializer.
